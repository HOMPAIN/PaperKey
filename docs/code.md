# Устройство кода PaperKey

Карта репозитория для тех, кто хочет разобраться в коде, что-то поправить или написать свой сканер. Что такое карточка и как она защищает ключ — в [paperkey.md](paperkey.md); точные правила формата — в [SPEC.md](SPEC.md).

## 1. Структура

```
PaperKey.slnx                 решение .NET 10
global.json                   закрепляет версию SDK
src/
  PaperKey.Core/              ядро: формат, генерация, раскладка, рендеринг, распознавание, ключи
  PaperKey.Web/               веб-приложение Blazor WebAssembly: генератор, проверка листа, сканирование
tests/
  PaperKey.Tests/             тесты xUnit и тестовые картинки
tools/
  PaperKey.Render/            консольный инструмент: листы, стороны, прогон распознавания по фото
  PaperKey.Vectors/           генератор тестовых векторов (две независимые реализации Argon2id)
docs/                         документация, тестовые векторы, картинки
samples/                      образцы листов, сделанные генератором
```

Все вычисления, которые имеют смысл вне браузера, живут в `PaperKey.Core` без зависимостей от веба. `PaperKey.Web` — тонкая оболочка: форма, камера, вывод. Благодаря этому одно и то же распознавание прогоняется в тестах на картинках, в консольном инструменте на фотографиях и в браузере на кадрах камеры.

## 2. PaperKey.Core

### Корень — формат и ключи

| Файл | Что в нём |
|---|---|
| `CardFormat.cs` | Все константы формата v1: 28 × 16 клеток, 112 печатных, максимум 168 меток, соль и параметры Argon2id, префикс HKDF. Менять эти числа — менять формат. |
| `SideGrid.cs` | Состояние одной стороны: 448 булевых клеток, индекс `строка · 28 + столбец`. Каноническая упаковка в 56 байт (`ToBytes`, старший бит первым) и обратно. |
| `CardGenerator.cs` | Случайное печатное заполнение: тасование 448 индексов через `RandomNumberGenerator.Shuffle`, первые 112. `Card` — пара сторон. `System.Random` в проекте запрещён. |
| `ProtectionLevel.cs` | Уровень защиты по числу закрашенных клеток: `Protection.Evaluate` для карточки (биты обеих сторон), `SideProtection.Evaluate` для одной стороны, `Log2Binomial` — вся арифметика стойкости. |
| `KeyDerivation.cs` | Мастер-ключ `Argon2id(S_A ‖ S_B)` (библиотека Konscious — для тестов и инструментов, в браузере не работает, см. п. 3), ключи приложений через HKDF, пароли (`Password` — из первых бит ключа по 6 бит на символ base64url; `AppPassword` — из `K_app` по нормализованному имени сервиса, `NormalizeAppId`; SPEC, п. 6.3). |
| `Fonts/` | PT Sans Regular и Bold (OFL) — встраиваются в PDF и отдаются странице как веб-шрифт. |

### `Layout/` — геометрия карточки и листа

| Файл | Что в нём |
|---|---|
| `Primitives.cs` | Примитивы рисования в миллиметрах: `RectShape`, `LineShape`, `TextShape`, цвет, `Sheet` — лист как список примитивов. Всё, что печатается, сначала становится этим списком. |
| `CardSize.cs` | Три размера карточки и их габариты: стандарт, узкая, мини (масштаб 2/3). |
| `CardLayout.cs` | Отрисовка одной стороны по спецификации: таблица, маркеры, подпись `PaperKeyA/B`, название, нумерация. Координаты блока 85,6 × 45 одинаковы для обеих сторон; сторона B зеркалит только номера строк. Название всегда в левой полосе, подпись стороны — в правой (на B с чёрным блоком), чтобы название не попадало в зону, по которой сканер определяет сторону. Константы положения элементов — здесь. |
| `SheetLayout.cs` | Лист целиком: `SheetRequest` (название, размер, число карточек, режим, бумага), `GenerateCards`, `Compose` — карточки одна под другой, линии сгиба, инструкция с переносом строк по метрикам шрифта и таблица уровней. |

### `Rendering/` — вывод

| Файл | Что в нём |
|---|---|
| `SvgRenderer.cs` | Список примитивов → SVG в миллиметрах. Используется для предпросмотра, печати из браузера и картинок подсказок. |
| `Pdf/PdfWriter.cs` | Список примитивов → PDF. Собственная минимальная реализация без библиотек: прямоугольники, линии, текст, встраивание TrueType как CIDFontType2, сжатие Flate, таблица xref, признак печати без масштабирования. |
| `Pdf/TrueTypeFont.cs` | Разбор TTF ровно в объёме, нужном PDF и измерению текста: таблицы head, hhea, maxp, hmtx, cmap, OS/2. |
| `FontMetrics.cs` | Загрузка встроенных шрифтов и измерение ширины строки в миллиметрах. |

Числа во всём выводе форматируются с инвариантной культурой — в русской локали иначе появляются запятые.

### `Vision/` — распознавание по фотографии

| Файл | Что в нём |
|---|---|
| `GrayImage.cs` | Полутоновое изображение: из RGBA, уменьшение, билинейная выборка, бинаризация относительно локального уровня бумаги (80-й процентиль по блокам; блок, залитый клетками, берёт уровень у соседей — так не теряется тонкая рамка и не мешает фон светлее бумаги). |
| `ConnectedComponents.cs` | Связные области тёмных пикселей с габаритами и крайними точками по диагоналям — из них берутся углы рамки. |
| `Homography.cs` | Проективное преобразование по четырём парам точек (Гаусс 8 × 8). |
| `SideChecker.cs` | Главный конвейер: поиск рамок таблиц (области тёмного плюс четырёхугольники по длинным пробегам линий), уточнение рамки по четырём маркерам (поиск ±4 мм, ключ «тёмное кольцо, светлый ореол») и по линиям рамки в ±0,75 мм, выравнивание 29 × 17 вершин сетки по пикам производной (края печатных клеток и линии сетки; бумага не плоская), аналоговая заполненность клеток по четырём вершинам клетки (центральные 60 % клетки, вес `(1 − u²)(1 − v²)`, локальный уровень бумаги: окно, квадратичная поверхность и собственная светлота клетки), маркеры → ориентация, блок подписи → сторона. `AnalyzeAll` возвращает все стороны на снимке. Там же `SideReader` — чтение готовой карточки по порогам режима чтения и пороги режима проверки. |
| `PngReader.cs` | Минимальный декодер PNG для тестов и инструментов; в браузере картинки декодирует сам браузер. |

## 3. PaperKey.Web

Blazor WebAssembly без сервера: после загрузки страница не делает сетевых запросов, CSP в `wwwroot/index.html` запрещает сторонние адреса. Три страницы:

| Страница | Файл | Что делает |
|---|---|---|
| `/` — генератор | `Pages/Home.razor` | Форма (название, размер, число карточек, режим, бумага), подсказки «?» с картинками (`Components/HelpTip.razor`, `HelpImages.cs`), предпросмотр SVG, три способа печати: скачать PDF, печать из браузера, PDF в новой вкладке (`wwwroot/js/paperkey.js`). |
| `/check` — проверка листа | `Pages/Check.razor` | Камера или фото из файла → обе стороны несложенной карточки → цветная разметка клеток (зелёная / жёлтая / красная), счётчики, уровень каждой стороны и карточки. |
| `/scan` — сканирование | `Pages/Scan.razor` | Готовая карточка с двух сторон, сторона определяется сама. Под камерой лента из трёх снимков: новый встаёт слева (нераспознанный предыдущий заменяется), пока идёт распознавание — кружок, затем по классам клеток режима проверки: зелёный «A ✓» (все клетки уверенные), жёлтый «A !» (есть слабые, но сторона читается), красный «A ✗» / «Error» (есть сомнительные, сторона не определена или таблица не найдена). Зелёный и жёлтый снимок даёт прочтение стороны и вытесняет прежний снимок той же стороны, красный ничего не заменяет и сам заменяется следующим снимком. Сканер читает по одной стороне за снимок: разворот с двумя сторонами — красный «Error». Нажатие на снимок открывает окно поверх страницы: крупное фото с разметкой и сведения как на странице проверки (`Texts.LevelName` общий для обеих страниц); все сведения о распознавании только там, закрывается нажатием в любом месте или на снимок. Разделы паролей и ключа свёрнуты, описание каждого — в подсказке «?» в шапке (`HelpTip`, текст — разметка); пока ключа нет, разделы показаны заблокированными, нажатие объясняет, что сначала нужны обе стороны. Поле имени сервиса само приводит буквы к строчным (NFC). Пустые места в ленте не рисуются; камера и сброс — кнопки с иконкой. Холсты снимков живут в `camera.js` по ключу. После обеих сторон — три раздела: единичный пароль из `K`, мастер-пароль (поле имени сервиса → пароль из `K_app`), ключ карты в hex. |
| `/help`, `/help/{раздел}` — справка | `Pages/Help.razor` | Документация из `docs/*.md` внутри приложения: файлы встраиваются в сборку при компиляции (`EmbeddedResource` в `PaperKey.Web.csproj`, список разделов — `Docs.cs`), картинки `docs/images` подключены как статические файлы, Markdown рисует собственный мини-рендерер `Markdown.cs` (заголовки, списки, таблицы, код, ссылки, картинки; ссылки на соседние `.md` ведут на разделы справки). Dev-сервер отдаёт подключённые через `Link` файлы (шрифты, картинки) пустыми — смотреть их нужно в опубликованной версии. |

Каркас — `Layout/MainLayout.razor` и `Layout/NavMenu.razor`: как в шаблоне Blazor, на широком экране (от 641 px) меню — колонка слева, на телефоне — полоса сверху с кнопкой, раскрывающей список; список закрывается при переходе. Стили каркаса — в `wwwroot/css/app.css` (раздел «Каркас»), без Bootstrap.

Скрипты в `wwwroot/js`:

- `paperkey.js` — скачивание PDF, печать, открытие PDF по временной ссылке.
- `camera.js` — камера: запуск с выбором устройства и предпочтением основной задней камеры, снимок из видеопотока с обрезкой по рамке видоискателя, загрузка фото из файла, рисование разметки поверх снимка. Кадр уходит в .NET как полутоновый буфер.
- `crypto.js` — Argon2id через `vendor/argon2.umd.min.js` (hash-wasm, MIT). Управляемая реализация в WebAssembly зависает: она ждёт потоки, которых у страницы нет. Параметры берутся из `CardFormat`; совпадение с .NET-реализацией проверяется тестовыми векторами.

Путь данных при сканировании: `camera.js` → байты → `GrayImage` → `SideChecker.AnalyzeAll` → `SideReader.ToGrid` → `S_A`, `S_B` → `crypto.js` (Argon2id) → `KeyDerivation.Password`.

Статика: `css/app.css` подключён с версией в адресе (`?v=N`, поднимать при изменении), скрипты — с отпечатком сборки (`#[.{fingerprint}]`). Шрифты в `wwwroot/fonts` — ссылки на файлы ядра, задаются в `PaperKey.Web.csproj`.

## 4. Тесты — `tests/PaperKey.Tests`

| Файл | Проверяет |
|---|---|

| `CardGeneratorTests.cs` | Ровно 112 клеток, карточки различаются, частота каждой клетки около 25 % на 3000 генерациях. |
| `ProtectionTests.cs` | Числа стойкости из документации, границы уровней, перекос сторон, недопустимые значения, отсутствие достижимых сумм у границ; пароль из ключа. |

| `RenderingTests.cs` | Шрифты, положение элементов на всех размерах, зеркальность стороны B, вместимость листа, режимы копий и названий, корректность SVG, структура PDF (xref, шрифты, размер страницы). |
| `VisionTests.cs` | Гомография; распознавание отрисованных сторон (`Assets/side-*.png`: 112 печатных и имитация точек, в том числе повёрнутый на 180° снимок); уровни стороны; настоящие фотографии с телефона (`Assets/photo-*.png`: пустая, аккуратная, небрежная карточка). |

Запуск:

```bash
dotnet test PaperKey.slnx
```

Тестовые картинки `side-*.png` делаются инструментом (см. п. 5) и Edge в headless-режиме; рядом лежат `.cells` — индексы клеток с точками. Фотографии уменьшены до 1800 px по ширине.

## 5. Инструменты — `tools/`

`PaperKey.Render` — всё из командной строки, без браузера:

```bash
dotnet run --project tools/PaperKey.Render -- <папка> [название] [standard|compact|mini] [число] [copies]
```
лист в PDF и SVG;

```bash
dotnet run --project tools/PaperKey.Render -- side <папка> <A|B> [точек]
```
одна сторона с фиксированным узором и точками «маркером» — заготовка тестовой картинки;

```bash
dotnet run --project tools/PaperKey.Render -- check <фото.png> [ширина]
```
прогон распознавания по фотографии: по каждой стороне числа, сомнительные клетки, крайние значения, рядом с фото — `.check.svg` с разметкой;

```bash
dotnet run --project tools/PaperKey.Render -- key <сторонаA.png> <сторонаB.png>
```
чтение двух сторон и вычисление ключа с паролем — для сверки с браузером.

```bash
dotnet run --project tools/PaperKey.Render -- check-dir <папка> [ширина]
```
прогон по всем PNG в папке (например, по сессии фотостенда): строка на снимок, затем по каждой стороне мажоритарное прочтение и список клеток, где снимок с ним расходится или сомневается (с заполненностью). Ключ `-v` печатает трассу поиска: области, четырёхугольники, маркеры, пристрелку сетки.

```bash
dotnet run --project tools/PaperKey.Render -- paint <фото.png|папка> [ширина]
dotnet run --project tools/PaperKey.Render -- cell <фото.png> <A|B> <строка> <столбец> <выход.png>
dotnet run --project tools/PaperKey.Render -- mask <фото.png> [ширина]
dotnet run --project tools/PaperKey.Render -- crop <фото.png> <x> <y> <ш> <в> <масштаб> <выход.png>
```
отладка распознавания: раскраска клеток поверх фото в `.check.png` (зелёная — уверенно, жёлтая — слабо, красная — сомнительно, рамка синяя, тонкими полупрозрачными линиями — выровненная сетка по всем вершинам; пороги режима проверки), окрестность клетки с контуром её четырёхугольника (увеличение ×4 — разглядеть, метка это или ошибка рамки), бинарная маска «тёмного» как её видит поиск рамки (`.mask.png` рядом с фото), просто увеличенный фрагмент.

`PaperKey.Vectors` пересчитывает `docs/test-vectors.json`; мастер-ключ записывается только при совпадении Konscious и Isopoh.

## 6. Сборка и запуск

Нужен .NET SDK 10. Сервер разработки:

```bash
dotnet run --project src/PaperKey.Web
```

Порт задан в `src/PaperKey.Web/Properties/launchSettings.json`. Камера в браузере работает только по https или на localhost; для телефона в той же сети:

```bash
dotnet run --project src/PaperKey.Web --launch-profile https --urls "https://0.0.0.0:7244"
```

Публикация — обычный `dotnet publish -c Release`, на выходе статические файлы для любого хостинга.

## 7. Где что менять

- Размеры, положение элементов карточки — `Layout/CardLayout.cs` и `Layout/CardSize.cs`, затем `docs/SPEC.md`.
- Текст инструкции на листе, таблица уровней — `Layout/SheetLayout.cs`.
- Границы уровней защиты — `ProtectionLevel.cs`; числа в документации считаются той же функцией.
- Пороги распознавания — константы в `Vision/SideChecker.cs` (`SideChecker` для проверки, `SideReader` для чтения); проверять инструментом `check` на фотографиях из `tests/PaperKey.Tests/Assets`.
- Параметры Argon2id, соль, префиксы — `CardFormat.cs`; это смена формата, меняет все ключи.
- Тексты страниц — `Pages/*.razor`; стили — `wwwroot/css/app.css` (не забыть поднять `?v=`).

## 8. Известные ограничения

- Распознавание настроено по базе фотостенда (6 сессий, 49 снимков: развороты и отдельные стороны, разный фон и свет): все снимки читаются, уверенные прочтения одной стороны совпадают. Клетки, где метка легла на линию сетки, честно помечаются сомнительными — их надо подкрасить.
- Распознавание и Argon2id в браузере блокируют вкладку на время работы: WebAssembly в Blazor однопоточный. Argon2id через hash-wasm укладывается в секунду; распознавание кадра 1600 px — около 1,5 с на ПК в интерпретаторе (нативно 0,2 с). Код исполняет интерпретатор Mono, поэтому в горячих циклах нет замыканий, LINQ и словарей; поэтапный профиль пишется в консоль браузера (`paperkey: …`) и печатается инструментом `check`. Следующий резерв — AOT-компиляция (`RunAOTCompilation`, нужна рабочая нагрузка `wasm-tools`).
- Контроль правильности чтения готовой карточки (чтобы ошибка в одной клетке не прошла незамеченной) ещё не реализован.
